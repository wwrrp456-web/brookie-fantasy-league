## الدورة: لما يقول المنظّم "Sonnet خلص" أو "Codex خلص"

### 1. اجمع الحالة
```bash
git fetch origin && git checkout <فرع جلستك> && git merge --ff-only origin/claude/broki-site-summary-qvjzoi
```
واسرد الـPRات المفتوحة (أداة GitHub: `list_pull_requests`، state=open).

### 2. راجع كل PR جديد
لكل PR:
1. **التقرير:** اقرأ `specs/reports/<المهمة>.md` من فرع الـPR.
2. **المعايير:** افتح المهمة في `NNN-*/tasks.md`، واكتب كل معيار قبول في جدول.
3. **النطاق:** `git diff --stat origin/claude/broki-site-summary-qvjzoi...origin/<الفرع>`. أي ملف خارج المذكور في المهمة = 🔁 (إلا التقرير ولقطاته).
4. **الاختبارات:** شغّل `node tests/run.js` على فرع الـPR بنفسك (worktree مؤقت في مجلد scratchpad).
5. **البصري:** افتح اللقطات (Read على الصورة)، وتأكد إن المطلوب ظاهر فعلًا. صفحات `_sheet.html` و`_compare.html` تحتاج سيرفر: `python3 -m http.server`.
6. **الكود (لـSonnet):** اقرأ الـdiff. ركّز على: الحالات الحدّية، والتعديل في دوال غير مطلوبة، وألوان hex جديدة، وإيموجي في الواجهة، و`innerHTML` بمحتوى زوار بدون تعقيم.
7. **الرسومات (لـCodex):** قائمة المراجعة في آخر `001-ui-visual-overhaul/codex-briefs.md`.

### 3. اكتب الحكم
ملف `specs/reports/<المهمة>-review.md` بهالشكل:
```markdown
# مراجعة <المهمة> · <العنوان>
**PR:** #N · **تقرير المنفّذ:** `<المهمة>.md`

## حكم المراجع
**✅ موافقة على الدمج** · SHA `<الـSHA الكامل 40 حرف>` · <التاريخ>
| المعيار | النتيجة |
|---|---|
**ملاحظات (ما تمنع الدمج):** …
```
- **✅** = كل المعايير متحققة. الملاحظات الصغيرة تنكتب وتنحط في مهمة لاحقة.
- **🔁** = معيار غير متحقق، أو ملف خارج النطاق، أو اختبار فاشل. اكتب أمر متابعة محدد في ملف المنفّذ.
- **⏸️** = يحتاج ذوق أو قرار من المنظّم (اعتماد بصري مثلًا). اسأله في المحادثة.
- الـSHA الكامل: `git rev-parse origin/<الفرع>`.

### 4. حدّث ملفات الأوامر
- **`agents/SONNET.md`:**
  - علّم الأمر المنجز ✅ مع رقم الـPR.
  - أضف أمر دمج لكل ✅ (`### ⬜ Mn · ادمج PR #N` + SHA + ملف الحكم + المهمة اللي تتعلّم ✅ بعد الدمج).
  - أضف المهام التالية من `MASTER-PLAN.md` اللي صارت اعتمادياتها جاهزة، **بنفس صيغة الأوامر الموجودة** (المرجع، والفرع، والمطلوب، والأدلة، والتقرير). وحط **⏹️ توقف بعده** عند نهاية الدفعة.
- **`agents/CODEX.md`:** نفس الشي لأوامر الرسومات، والأمر الكامل يحيل لقسم BRIEF في `codex-briefs.md`.
- **`QUEUE.md`:** حدّث جدول "الآن" وقسم "منجز".
- **`MASTER-PLAN.md`:** علّم الخطوة المنجزة ✅ في عمود "#" (مثل `✅ B1`).

### 5. ارفع
```bash
git add -A specs && git commit -m "مراجعة PR #N (<المهمة>): ✅/🔁" && git push origin HEAD:claude/broki-site-summary-qvjzoi
```
رسالة الـcommit بالعربية، وتنتهي بسطور الإسناد المطلوبة في الجلسة.

### 6. رد على المنظّم (قصير)
```
✅ #N <وصف بكلمات>   (أو 🔁 مع السبب بسطر)
ملاحظة: <وحدة إن وُجدت>
أرسل لهم الجمل.   (أو: أرسل لـSonnet بس / لـCodex بس)
```

## قواعد اختيار المهام التالية
1. امشِ على ترتيب `MASTER-PLAN.md`، ولا تاخذ مهمة قبل ما تتحقق كل اعتمادياتها (مدموجة، مو بس عليها ✅).
2. الدفعة الواحدة لـSonnet: 2 إلى 4 مهام مستقلة، أو مهمة كبيرة وحدة. ولـCodex: أمر واحد أو اثنين.
3. لا تعطي مهمتين يعدّلون نفس الملف في نفس الدفعة إلا بالتسلسل.
4. خطوات 👤 تُطلب من المنظّم في الرد، بسطر واحد.
5. خطوات 🧠 ما تنفذها. قل للمنظّم: "الخطوة X تحتاج Opus، رجّع النموذج له وقل: نفّذ X من MASTER-PLAN".

## متى تقول للمنظّم "رجّع النموذج لـOpus"
- أي حالة في قسم **نقاط التصعيد** في `MASTER-PLAN.md`.
- لو احترت في حكم بين ✅ و🔁 لسبب يمس الدستور أو قرار R.
- لو المنفّذ كتب في تقريره إن المواصفة متعارضة أو ناقصة.

قبل التصعيد اكتب في `QUEUE.md` تحت قسم "ينتظر Opus": المشكلة بسطرين، والملفات المعنية. عشان Opus يبدأ مباشرة بدون شرح.
