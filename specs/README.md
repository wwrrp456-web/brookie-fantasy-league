# مواصفات دوري بروكي (Spec-Driven Development)

هذا المجلد هو **المرجع الوحيد** لأي تطوير في المشروع. أي شغل، سواء نفّذه Claude أو Codex، يبدأ من ملف هنا وينتهي بتحقق مكتوب هنا.

## المنهجية: 4 مراحل، ولا ننتقل لمرحلة قبل اعتماد اللي قبلها

| المرحلة | الملف | السؤال | من يعتمده |
|---|---|---|---|
| 0. الدستور | `constitution.md` | وش المبادئ اللي ما نكسرها؟ | المنظّم |
| 1. المواصفات | `NNN-*/spec.md` | **وش** نبي و**ليش**؟ | المنظّم |
| 2. الخطة | `NNN-*/plan.md` | **كيف** تقنيًا؟ | Claude Opus يكتب، والمنظّم يراجع |
| 3. المهام | `NNN-*/tasks.md` | مهام صغيرة بمنفذ ومعيار قبول | تُنفَّذ واحدة واحدة |

**قاعدة ذهبية:** لو اكتشفنا أثناء التنفيذ إن المواصفة غلط، **نعدّل المواصفة أولًا** ثم الكود.

## الأدوار (Q-25ب)

| الدور | المسؤولية |
|---|---|
| **المنظّم** | يعتمد كل `spec.md`، ويقرر الذوق البصري واللغوي |
| **Claude Opus** | المواصفات والخطط والمهام، ومراجعة كل PR بصريًا وتقنيًا ولغويًا |
| **Claude Sonnet** | تنفيذ مهام البرمجة |
| **Codex** | التوليد البصري: أيقونات، وتحسين الشعارات، وقوالب الكروت، والصور |

## دورة العمل لكل مهمة

```
1. اختر المهمة التالية من tasks.md (اللي كل اعتمادياتها ✅)
2. افتح فرع:  feat/NNN-Txx-وصف-قصير   (أو codex/NNN-Txx للرسومات)
3. نفّذ
4. التحقق الآلي يشتغل على الـPR: tests + lint + snap
5. لو عدّى التحقق ← دمج تلقائي (Q-27)، ولو فشل ← يرجع للمنفّذ
6. علّم المهمة ✅ في tasks.md
```
