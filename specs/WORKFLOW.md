# منهجية العمل اليومية (R-11)

> هذا الملف يحدد **مين يسوي وش، وبأي ترتيب، وكيف تنتقل المهمة من واحد للثاني**.
> المبادئ في `constitution.md`، والمهام نفسها في `NNN-*/tasks.md`، واللوحة الحية في `QUEUE.md`.

---

## 1. الأدوار

| الدور | يسوي | ما يسوي |
|---|---|---|
| 👤 **المنظّم** | يعتمد المواصفات والذوق، ويوصّل الرسائل بين الجلسات (ينسخ الأوامر الجاهزة) | ما يكتب كود |
| 🔍 **Opus** (المخطط والمراجع) | يكتب ويعدّل spec وplan وtasks، ويسجّل القرارات، ويرتّب `QUEUE.md`، ويراجع كل PR ويكتب **حكم المراجعة** | **ما يدمج، وما ينفّذ كود**، وما يشغّل فحوص طويلة (توفيرًا للحد) |
| 🛠️ **Sonnet** (المنفّذ والمدمِج) | ينفّذ مهام البرمجة، و**يدمج** أي PR عليه حكم ✅ من Opus، ويحل التعارضات، ويعلّم المهام ✅ في `tasks.md` و`QUEUE.md` | ما يدمج بدون حكم ✅، وما يغيّر spec أو قرار من عنده |
| 🎨 **Codex** (الرسام) | الأيقونات والشعارات والقوالب والصور، داخل `assets/` فقط | ما يلمس `js/` أو `css/` أو `index.html` أو `specs/` |

## 2. الفروع

- **فرع التكامل:** `claude/broki-site-summary-qvjzoi`. كل الشغل يبدأ منه ويندمج فيه.
- **فرع لكل مهمة:** `feat/NNN-Txx-وصف` لـSonnet، و`codex/NNN-Txx` لـCodex، و`specs/وصف` لتعديلات Opus على المواصفات.
- **كل PR قاعدته فرع التكامل**، ولا شي يروح لـ`main` مباشرة.
- **الدمج في `main`** قرار منفصل للمنظّم، وينفّذه Sonnet لما يطلبه المنظّم.

## 3. دورة المهمة

```
 Opus                 المنفّذ (Sonnet/Codex)        Opus                  Sonnet
 ┌──────────┐        ┌───────────────────┐        ┌───────────┐         ┌────────────────┐
 │ المهمة في │  ───►  │ فرع ← تنفيذ ← PR   │  ───►  │ مراجعة +  │  ✅ ──►  │ دمج + تعليم ✅  │
 │ QUEUE.md │        │ + أدلة في وصف PR   │        │ حكم مكتوب │         │ + تحديث QUEUE  │
 └──────────┘        └───────────────────┘        └───────────┘         └────────────────┘
                              ▲                          │ 🔁
                              └──── أمر متابعة جاهز ◄────┘
```

1. **Opus** يحط المهمة في `QUEUE.md` مع المنفّذ والأمر الجاهز.
2. **المنظّم** ينسخ الأمر للمنفّذ.
3. **المنفّذ** يفتح فرع من فرع التكامل، وينفّذ، ويفتح PR فيه **الأدلة**: نتيجة `node tests/run.js`، ولقطات قبل/بعد، و`REPORT.md` لـCodex. وبعد T11 تُضاف نتيجة فحص `verify`.
4. **المنظّم** يرسل لـOpus: "راجع PR رقم N".
5. **Opus** يراجع ضد معايير القبول، ويكتب **حكم المراجعة** كتعليق على الـPR بهالصيغة:
   - `✅ حكم Opus: موافقة على الدمج` مع آخر SHA راجعه
   - أو `🔁 حكم Opus: يحتاج تعديل` مع أمر متابعة جاهز للمنفّذ
   - أو `⏸️ حكم Opus: ينتظر قرار المنظّم` مع السؤال
6. **المنظّم** يرسل لـSonnet: "ادمج PR رقم N".
7. **Sonnet** يدمج **بشرط** إن آخر حكم ✅ وعلى نفس الـSHA الحالي للـPR، ثم يعلّم المهمة ✅ في `tasks.md` و`QUEUE.md`، ويحدّث `HANDOFF.md` لو تغيّرت المرحلة.

> **قاعدة الـSHA:** لو انضاف commit بعد حكم ✅، الحكم يسقط ويرجع الـPR لـOpus.

## 4. تعديل المواصفات

- Opus يكتب التعديل على فرع `specs/…` ويفتح PR، ويكون الحكم ✅ مكتوب في وصفه مباشرة.
- Sonnet يدمجه مثل أي PR.
- قرار جديد من المنظّم = رقم R جديد في `decisions.md` قبل أي تنفيذ.

## 5. توفير الحد

- **Opus:** يقرأ أدلة الـPR أولًا، ويشغّل بنفسه فقط فحوص قصيرة ومحددة. ما يدمج، وما يحل تعارضات، وما يكتب كود.
- **Sonnet:** كل شي تنفيذي وتكراري: دمج، وتعارضات، وتحديث لوحات، وتشغيل لقطات.
- **جلسة Opus وحدة طويلة للمراجعة** أفضل من جلسات كثيرة، لأن السياق محفوظ فيها.

## 6. أوامر جاهزة للمنظّم

**لـSonnet (تنفيذ):**
```
أنت Sonnet في مشروع دوري بروكي. اقرأ AGENTS.md و specs/WORKFLOW.md أولًا.
نفّذ <NNN-Txx> من specs/<feature>/tasks.md.
ابدأ من claude/broki-site-summary-qvjzoi، وافتح فرع feat/<NNN-Txx-وصف>، و PR قاعدته نفس الفرع،
مع الأدلة المطلوبة في معايير القبول. لا تدمج.
```

**لـSonnet (دمج):**
```
أنت Sonnet في مشروع دوري بروكي. اقرأ specs/WORKFLOW.md (القسم 3).
ادمج PR رقم <N> في claude/broki-site-summary-qvjzoi، بشرط: آخر تعليق "✅ حكم Opus" على نفس
SHA الحالي للـPR. لو فيه تعارض حلّه بدون تغيير المعنى، ولو ما تقدر توقف واكتب السبب.
بعد الدمج: علّم المهمة ✅ في tasks.md و specs/QUEUE.md، وارفع التحديث على فرع التكامل.
```

**لـOpus (مراجعة):**
```
راجع PR رقم <N> ضد معايير القبول في tasks.md، واكتب حكمك على الـPR حسب specs/WORKFLOW.md.
```

**لـCodex:** الأمر الكامل يكون جاهزًا في `QUEUE.md` أو `codex-briefs.md`.
