# دستور مشروع دوري بروكي

> مبادئ لا تتغير بين الميزات. أي مواصفة أو خطة أو كود يخالفها يُرفض في المراجعة.
> آخر تعديل: 29 أكتوبر 2026

## 1. المنتج
1. **الجوال أولًا.** أغلب الزوار يفتحون الرابط من مجموعة الواتساب على الجوال. كل تصميم يُعتمد على عرض **390px** أولًا، ثم الكمبيوتر.
2. **العربية أولًا، من اليمين لليسار.** النصوص والأرقام والاتجاهات والأسهم كلها تُصمَّم لـRTL من البداية، مو تُقلب لاحقًا.
3. **صحة الأرقام فوق الجمال.** أي رقم يظهر (نقاط، ترتيب، عدد مشاركين/أندية/دوريات) يُحسب من مصدر واحد، وما يُكتب يدويًا في النصوص.
4. **الكرت المشارَك هو واجهة الدوري.** كروت الصور (بطل الجولة، الترتيب، الستوري، الشهادة) لها نفس أولوية الموقع أو أعلى، لأنها اللي تنتشر في المجموعة.

## 2. التصميم
5. **نظام تصميم واحد.** كل لون ومسافة وحجم خط وزاوية دوران يأتي من رموز (Design Tokens) في ملف واحد. ممنوع كتابة لون hex مباشرة في CSS أو JS للميزات.
6. **لا إيموجي كأيقونات واجهة.** الإيموجي يتغير شكله بين آيفون وأندرويد والكمبيوتر. الأيقونات من مكتبة SVG موحّدة. يُسمح بالإيموجي فقط داخل نصوص المحادثة (الجدار، التعليقات).
7. **هرمية بصرية واضحة.** لون تمييز أساسي واحد (بنفسجي بروكي)، وألوان دلالية محددة: ذهبي للبطولة، أخضر للصعود، أحمر للهبوط/الخطر. أي لون إضافي يحتاج تبرير في المواصفة.
8. **لا شعارات رسمية.** شعارات الأندية **تصاميم أصلية مستوحاة** (ألوان النادي ورمز مميز)، وما تُنسخ الشعارات المسجلة.
9. **حالة فاضية محترمة.** أي عنصر ما عنده بيانات يعرض رسالة مفهومة أو يختفي، ولا يعرض "–" أو "0" مضلل.

## 3. التقنية
10. **بدون خطوة بناء.** المشروع يبقى HTML/CSS/JS يشتغل بفتح الملف أو من GitHub Pages مباشرة، بدون npm install.
11. **مصدر واحد للحقيقة.** لا تكرار للصفحات أو البيانات (`index.html` هو الصفحة).
12. **كل تغيير بصري يُتحقق منه بصريًا.** لقطات شاشة آلية (`tools/snap.js`) قبل وبعد، على عرض 390 و1366، وتُرفق في الـPR.
13. **الاختبارات تبقى خضراء.** `node tests/run.js` يمر قبل أي دمج، وأي إصلاح لمنطق الحساب يضيف اختبارًا.
14. **محتوى المستخدم يُعقّم.** أي نص يكتبه زائر (الجدار، التقارير، التعليقات) يمر عبر دالة escape قبل `innerHTML`.

## 4. العمل
15. الردود والتعليقات وملفات المواصفات **بالعربية**، وأسماء الملفات والمتغيرات والدوال **بالإنجليزية**.
16. مهمة واحدة = فرع واحد = PR واحد صغير قابل للمراجعة.
17. مخرجات Codex لا تُدمج قبل مراجعة Claude البصرية والتقنية ضد معايير القبول.
